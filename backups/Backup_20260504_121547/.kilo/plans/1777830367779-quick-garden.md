# App Startup Failure - Fix Plan

## Problem
The batch file / `npm run tauri:dev` fails to start the app. The process runs `Elite-Reset.ps1` then `tauri dev`, but the app does not launch.

## Root Cause
The `Elite-Reset.ps1` script uses `Get-NetTCPConnection`, which may fail on some Windows environments (missing module, permissions, or PowerShell version). When this command fails, the script may hang or exit with error, causing `npm run clean` to fail, which aborts the entire `pretauri:dev` step. As a result, `tauri dev` never starts.

## Solution
Modify `Elite-Reset.ps1` to safely handle failures from `Get-NetTCPConnection` and continue execution even if port checks fail.

### Changes to `Elite-Reset.ps1`
Replace lines 11–17 with a safer version that:
- Uses `try`/`catch` or `-ErrorAction Stop` with `try` to avoid termination
- Falls back to `netstat` or skips port killing if `Get-NetTCPConnection` is unavailable
- Never blocks startup

Proposed replacement:
```powershell
# 1. Kill any process locking the target ports (safe version)
foreach ($port in @($TARGET_PORT, $VITE_PORT)) {
    try {
        $portProcess = Get-NetTCPConnection -LocalPort $port -ErrorAction Stop | Select-Object -ExpandProperty OwningProcess -First 1
        if ($portProcess) {
            Write-Host "Terminating zombie process on port $port (PID: $portProcess)..." -ForegroundColor Yellow
            Stop-Process -Id $portProcess -Force -ErrorAction SilentlyContinue
        }
    } catch {
        # Fallback: try netstat or just continue
        Write-Host "Could not query port $port (may require admin or module). Continuing..." -ForegroundColor DarkYellow
    }
}
```

This ensures the script never fails the build.

## Why This Fixes It
- The startup process is blocked by a failing PowerShell command, not by app code.
- Making the port-killing step non-fatal allows `tauri dev` to run.
- All other fixes (modes, video mute, etc.) are irrelevant if the app won’t start.
