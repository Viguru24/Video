# Window Drag and Resize Fix - Implementation Plan

## Problem Statement
The frameless Cosmo Video Tauri application cannot be dragged or resized using the mouse. Users report:
- Cannot move/drag the window from the top area
- Cannot resize from border arrows
- Minimize/maximize/close buttons don't work

## Root Cause Analysis

### 1. Tauri Capability Permissions Missing
The `src-tauri/capabilities/default.json` file lacks required permissions for window manipulation:
- `core:window:allow-start-dragging`
- `core:window:allow-start-resize-dragging`

Without these, Tauri blocks the JS API calls at the Rust level.

### 2. Incorrect Tauri v2 API Usage
The `ResizeHandles.tsx` component uses `startResizing()` which is deprecated/incorrect for Tauri v2. The correct API is `startResizeDragging()`.

### 3. Z-Index Stacking Conflict
- `.header-drag-handle` has `z-index: 1001` and covers top 48px
- `.resize-handle` has `z-index: 9999` (was) → needs to be higher
- `.app-header` has `z-index: 1000`

The drag handle creates a stacking context that can block resize handles.

### 4. Pointer-Events Cascade Blocking
- `.header-row-brand` has `pointer-events: none`
- `.window-controls` is INSIDE `.header-row-brand` (line 222 in ControlBar.tsx)
- Despite `> *` rule setting `pointer-events: auto`, nested elements may not properly inherit
- `.window-controls` needs explicit `pointer-events: auto`

### 5. Resize Handle Hit Area Too Small
- Edge handles: 6px wide strips
- Corner handles: 12x12px squares
- Difficult for users to grab accurately

### 6. Missing ResizeHandles Component File
`ResizeHandles.tsx` exists but is untracked (new file). It must be properly committed.

## Solution Plan

### Phase 1: Tauri Configuration (REQUIRED)
**File: `src-tauri/capabilities/default.json`**
- Add `"core:window:allow-start-dragging"`
- Add `"core:window:allow-start-resize-dragging"`
- These are Rust-level permissions - without them, nothing works

### Phase 2: Fix ResizeHandles Component (REQUIRED)
**File: `src/components/ResizeHandles.tsx`**
- Change `getCurrentWindow().startResizing(direction)` 
- To: `getCurrentWindow().startResizeDragging(direction)`
- Add `e.preventDefault()` and `e.stopPropagation()`
- Add `.catch(console.error)` for error handling

### Phase 3: Fix Z-Index Stacking (REQUIRED)
**File: `src/index.css`**
- `.resize-handle`: `z-index: 10000` (must be above drag handle's 1001)
- `.header-drag-handle`: `z-index: 1001` (keep as is)
- `.app-header`: `z-index: 1000` (keep as is)

### Phase 4: Fix Pointer-Events for Controls (REQUIRED)
**File: `src/index.css`**
- `.window-controls`: Add `pointer-events: auto` explicitly
- This ensures buttons inside can receive clicks despite parent's `pointer-events: none`

### Phase 5: Increase Resize Handle Hit Area (RECOMMENDED)
**File: `src/index.css`**
- Edge handles: 6px → 8px (or 10px for better UX)
- Corner handles: 12x12px → 16x16px (or 20x20px)
- Makes them easier to grab

### Phase 6: Verify Component Integration (REQUIRED)
**File: `src/App.tsx`**
- Verify `import { ResizeHandles } from './components/ResizeHandles'`
- Verify `<ResizeHandles />` is rendered (line ~720)

**File: `src/components/ControlBar.tsx`**
- Verify `header-drag-handle` div exists with `startDragging()` call
- Verify `window-controls` div is inside `header-row-brand`

## Critical Notes

1. **Tauri capabilities are Rust-level** - Even with perfect JS/CSS, missing capabilities will silently fail
2. **`startResizeDragging` vs `startResizing`** - Tauri v2 renamed this method
3. **Z-index matters** - Resize handles MUST be above drag handle to work on overlapping areas
4. **Pointer-events cascade** - Parent `none` blocks all children unless explicitly overridden
5. **The `window-controls` is INSIDE `header-row-brand`** - This is why buttons don't work
